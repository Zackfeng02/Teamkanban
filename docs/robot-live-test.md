## 操作

在同一工作群中按顺序：

1. @机器人 KANBAN-TEST-4726
2. @机器人 TEST-LEAD 虚构客户A，需要跟进报价
3. 转发不含客户资料的测试图片，引用图片并 @机器人。
4. 将至少两条虚构文字及该图片合并转发，引用合并记录并 @机器人。第二条文字可用 TEST-POLICY 虚构保单B，需要变更地址。
5. 测试者确认已经发送后，对照本地 events.jsonl 中的 TEST_MESSAGE / IMAGE_DOWNLOADED。图片还需打开核对，收到一个卡片标题不代表已展开内容。

机器人不会自动回复。群聊是否产生消息回调与 @、引用和消息类型有关。没有观察到回调须结合发送动作和控制消息判断，不能直接宣称平台永久不支持。

## 接收器行为

- 首条测试口令绑定发送者与会话；其他会话和发送者忽略。
- 绑定后最多记录 12 条消息（去除相同 msgid），每条最多下载 4 张图片，十分钟自动停止。
- 元数据报告不含用户 ID、正文、媒体下载 URL 或解密密钥；只记录内容长度、测试标记、结构和摘要。
- 仅将绑定范围内的测试图片下载至 evidence/wecom-probe/，使用本地生成的文件名。
- 禁用自动回复、自动重连和认证失败重试。相同机器人新连接可能使旧连接下线，因此不能与生产后端同时测试。
- 凭据由进程环境传入，未写入项目配置文件；源码不包含凭据。
- 本地测试新增范围隔离、日志脱敏和引用结构检查，npm test 共 28 项通过。
